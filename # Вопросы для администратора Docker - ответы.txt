# Вопросы для администратора Docker/сервера

## Цель
Настроить автоматическое развертывание сайта: когда код изменяется в GitHub, сайт должен автоматически обновиться в Docker.

## Текущая ситуация
- Сайт уже работает в Docker контейнере
- Код проекта находится локально и планируется загрузить в GitHub
- Нужно связать GitHub → Docker для автоматических обновлений

## Вопросы о текущей настройке Docker

### 1. Информация о контейнере
- Как называется Docker контейнер с нашим сайтом?
- На каком порту работает сайт? (например: localhost:3000)
- Какой Docker образ используется?
- Есть ли docker-compose.yml файл?

### 2. Расположение файлов
- Где на сервере находятся файлы проекта?
- Как сейчас обновляется код в контейнере? (вручную?)
- Есть ли volume маппинг между сервером и контейнером?

### 3. Доступы и права
- Есть ли на сервере установленный Git?
- Может ли сервер получать доступ к GitHub (pull репозитория)?
- Нужны ли SSH ключи для доступа к GitHub?
- Есть ли права на перезапуск Docker контейнеров?

### 4. Автоматизация
- Есть ли опыт с GitHub Webhooks?
- Можно ли установить GitHub Actions runner на сервер?
- Предпочитаете ли вы webhook-подход или GitHub Actions?

### 5. Мониторинг и логи
- Как просматривать логи Docker контейнера?
- Есть ли система мониторинга развертываний?
- Нужны ли уведомления об успешных/неуспешных развертываниях?

## Предпочтения по развертыванию

Какой подход предпочитаете:

**Вариант А: GitHub Webhooks**
- GitHub отправляет уведомление на сервер при изменении кода
- Сервер автоматически обновляет контейнер
- Требует открытый endpoint на сервере

**Вариант Б: GitHub Actions**
- GitHub Actions собирает и отправляет новый образ
- Может использовать Docker Hub или собственный registry
- Не требует открытых портов на сервере

**Вариант В: Polling (опрос)**
- Сервер периодически проверяет изменения в GitHub
- Простой в настройке
- Менее оперативный

А = как по мне то лучше
Б = тоже хорош, но прийдется возиться с собственным registry
В = то что и А только со стороны сервера
