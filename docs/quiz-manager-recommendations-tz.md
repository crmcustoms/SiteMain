# ТЗ: Додавання рекомендацій для менеджера в квіз

---

## 📋 ЗАГАЛЬНА ІНФОРМАЦІЯ

**Мета:** Додати в результат квізу приховану секцію з рекомендаціями для менеджера, яка допоможе ефективно працювати з клієнтом на основі його типу.

**Базується на:** Методології кваліфікації клієнтів з відео-тренінгу (5 критеріїв: сфера діяльності, кількість осіб, етап автоматизації, вид автоматизації, ЛПР)

**Важливо:** Рекомендації описані на рівні контенту та логіки, без прив'язки до конкретної технології чи дизайну.

---

## 🎯 ОСНОВНА ЗАДАЧА

### Що потрібно зробити:

1. **Клієнт бачить** на сайті свій результат (як зараз)
2. **Менеджер отримує** в CRM/email ДВА блоки:
   - Результат клієнта (що клієнт бачив на сайті)
   - Рекомендації для менеджера (приховані від клієнта)

### Де зміни:

При відправці даних квізу в поле `htmlContent` потрібно включити:
- Клієнтський результат (існуючий)
- Роздільник
- Блок рекомендацій для менеджера (новий)

## 📊 ЛОГІКА РОБОТИ

### Поточна логіка:

```
Користувач відповідає → Заповнює контакти → Бачить результат на екрані
                                            ↓
                                   Дані відправляються:
                                   {
                                     answers: {...},
                                     contact: {...},
                                     clientType: "ideal",
                                     htmlContent: "HTML результату для клієнта"
                                   }
```

### Нова логіка:

```
Користувач відповідає → Заповнює контакти → Бачить результат на екрані (БЕЗ ЗМІН!)
                                            ↓
                                   Дані відправляються:
                                   {
                                     answers: {...},
                                     contact: {...},
                                     clientType: "ideal",
                                     htmlContent: "Результат для клієнта" + 
                                                  "Роздільник" +
                                                  "Рекомендації для менеджера"
                                   }
```

## 🔧 ТЕХНІЧНІ ВИМОГИ

### 1. Визначення типу клієнта

**Існуючі типи клієнтів:**
- `startup` - Стартап (1-3 особи, немає систем)
- `small` - Малий бізнес (3-15 осіб, немає CRM)
- `medium-risk` - Середній бізнес без систем (15-35 осіб, ризик)
- `ideal` - Ідеальний клієнт (є облікова система, немає CRM)
- `large` - Великий бізнес (35+ осіб)
- `has-crm` - Є CRM (оптимізація)

### 2. Нова функція генерації рекомендацій

Потрібно створити функцію, яка на основі типу клієнта повертає HTML/текст з рекомендаціями:

**Вхід:** 
- `clientType` - тип клієнта (один з 6)
- `answers` - відповіді клієнта з квізу (опційно, для деталізації)

**Вихід:** 
- HTML/текстовий блок з рекомендаціями

**Приклад структури виклику:**
```
generateManagerRecommendations(clientType, answers)
  → повертає HTML блок
```

### 3. Формування `htmlContent`

При відправці даних об'єднати три частини:

1. **Клієнтський результат** (існуючий)
2. **Роздільник** (візуальне розділення)
3. **Рекомендації менеджеру** (новий)

**Важливо:** Клієнт на сайті бачить ТІЛЬКИ пункт 1, без роздільника та рекомендацій.

### Візуальне оформлення:

**Стиль заголовка секції:**
- Виділений фон (жовтий/помаранчевий)
- Чітка рамка
- Технічна мітка "// INTERNAL USE ONLY"
- Великий заголовок "РЕКОМЕНДАЦІЇ ДЛЯ МЕНЕДЖЕРА"
- Підзаголовок "Ця інформація НЕ видима клієнту"

**Стиль контенту:**
- Структурований текст з заголовками
- Списки де необхідно
- Виділення важливих блоків кольором:
  - Попередження (жовтий/помаранчевий фон)
  - Успішні рекомендації (зелений фон)
  - Додаткова інформація (блакитний фон)
- Відступи між секціями

```

• Шукають "рожевого єдинорога"
• Немає грошей на повноцінне впровадження
• Власник в операційці 24/7
```

**3. ЧОГО ХОЧЕ КЛІЄНТ:**
```
• Швидко і недорого
• "Магічну кнопку" яка вирішить всі проблеми

**4. ХТО ЛПР:**
```
• Власник (єдиний)
```

**7. ЯК ПРАЦЮВАТИ:**

Малий бізнес - СТАРТ (25,000₴)

```

• Можливо є система обліку (1С, Medoc, Finsmart)

• Є базове розуміння що потрібно
• Готові інвестувати в розвиток
```

**3. ЧОГО ХОЧЕ КЛІЄНТ:**
```

• Не сильно розуміє в IT, почув від знайомих

```

**4. ХТО ЛПР:**
```

• Бачать що бізнес росте, а контролю немає

```

(базове впровадження + супровід рік + допрацювання)

- Команда 15-35 осіб
- Немає систем взагалі
- Проблема в менеджменті, а не технологіях
- Високий ризик провалу

**1. ТИП КЛІЄНТА:**
```
Середній бізнес без систем - РИЗИК
```

**2. ХАРАКТЕРИСТИКА:**
```
• Команда: 15-35 осіб
• Немає CRM, немає обліку, або все погано ведеться
• Хаос в управлінні
• Відсутня культура менеджменту
• Органічно доросли до цього розміру
• Все тримається на енергії власника
• Немає систематизації процесів
```

**3. ЧОГО ХОЧЕ КЛІЄНТ:**
```
• Вирішити проблему менеджменту через автоматизацію
• "Зажати гайки" через CRM
• Отримати контроль над людьми
• Думають що CRM вирішить проблему дисципліни

**4. ХТО ЛПР:**
```
• Власник який "затрахався" (60%)
• РОП який прийшов "навести порядок" (30%)

```

## 📋 ЗАГАЛЬНІ ПРАВИЛА ДЛЯ ВСІХ ТИПІВ

### 1. НІКОЛИ НЕ ВІДМОВЛЯЙ РІЗКО!

Навіть якщо клієнт не підходить:

❌ **Неправильно:**
- "Вам не підходить"
- "Приходьте коли виростете"
- "Ми не працюємо з такими"

✅ **Правильно:**
- "На вашому етапі важливіше X, але ми можемо..."
- "Повноцінне впровадження передчасне, але є варіант..."
- "Зараз не найкращий час, давайте..."

### 2. ЗАВЖДИ ПРОПОНУЙ АЛЬТЕРНАТИВИ

Для кожного типу є що запропонувати:
- Консультацію
- Мінімальний пакет
- Аудит
- Інші послуги
- Перенесення на пізніше

### 3. ЗАЛИШАЙ ПОЗИТИВНЕ ВРАЖЕННЯ

- Дай корисну пораду
- Порекомендуй безкоштовні інструменти
- Підкажи що робити далі
- Додай в список "розігріву"

Вони можуть:
- Повернутися коли виростуть
- Порекомендувати нас іншим
- Написати позитивний відгук

### 4. МЕТА МЕНЕДЖЕРА

- Зателефонувати протягом години
- З'ясувати справжню потребу
- Запропонувати рішення
- Закрити на послугу (будь-яку!)
- Залишити позитивне враження
